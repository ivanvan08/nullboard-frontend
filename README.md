# Nullboard frontend

Простий фронтенд для REST API анонімного форуму Nullboard (бекенд на Django REST Framework, репозиторій `nullboard`). Без фреймворків і збірки: чистий HTML, CSS і JavaScript (`fetch`). Тема оформлення: Omarchy "Osaka Jade".

## Можливості

- Навігація посиланнями і через адресний рядок (hash-роутинг), працюють Back/Forward і перезавантаження сторінки.
- Авторизація та реєстрація через JWT токени (`access` + `refresh`).
- Автоматичне оновлення (silent refresh) `access` токена у фоновому режимі при отриманні `401`.
- Розподіл прав доступу:
  - Неавторизований користувач (гість): перегляд дошок, тегів, тредів і відповідей. При спробі створити тред/відповідь або зайти в панель керування бачить повідомлення з пропозицією увійти, або перенаправляється на сторінку логіну.
  - Авторизований користувач: створення та редагування тредів і відповідей, відображення нікнейму та кнопки Logout у шапці.
  - Адміністратор: доступ до сторінки `#/admin` для створення та редагування дошок і тегів. Для звичайного юзера тут показується сторінка `403 Access Denied`.
- Розумна навігація: після логіну повертає на сторінку, з якої користувача перенаправило (параметр `?next=`). Авторизований користувач не може відкрити сторінки `/login` або `/register` (відбувається редирект на головну).
- Дошки: список, сторінка дошки з її тредами, створення, редагування, видалення.
- Теги: список, створення, редагування title, видалення.
- Треди: стрічка із сортуванням (Active / New / Most replies), створення (дошка, тема, текст, ім'я, теги), редагування, pin/unpin, lock/unlock, видалення.
- Пости: відповідь у треді, редагування і видалення кожного поста.
- Перед кожним видаленням `window.confirm`. Після кожної зміни сторінка заново завантажується з API.
- Відповіді API видно на сторінці: рядок статусу з кодом (`201 · board /sec/ created`, `409 · ...`), а помилки валідації (`fields`) показуються під відповідним полем форми.

## Маршрути

| Адреса | Сторінка |
| --- | --- |
| `#/` | список дошок і стрічка тредів (публічна) |
| `#/boards/{slug}` | одна дошка і її треди (публічна) |
| `#/threads/{id}` | тред: перший пост, відповіді, форма відповіді |
| `#/tags` | список тегів |
| `#/login` | форма входу (редирект на попередню сторінку після успішного входу) |
| `#/register` | форма реєстрації нового користувача |
| `#/admin` | панель адміністратора (керування дошками/тегами, захищена роллю `is_staff`) |

Невідома адреса або відповідь API `404` показує сторінку "not found" з повідомленням від API.

API не має фільтра `?board=`, тому сторінка дошки завантажує всі треди і відбирає треди цієї дошки на клієнті.

## Як запустити проєкт

1. Завантажити й запустити бекенд, репозиторій
   [ivanvan08/nullboard](https://github.com/ivanvan08/nullboard). Поки
   pull request не змерджений, API лежить у гілці `feat/crud-api`:

   ```bash
   git clone https://github.com/ivanvan08/nullboard.git
   cd nullboard
   git switch feat/crud-api
   python -m venv .venv
   source .venv/bin/activate        # Windows: .venv\Scripts\activate
   python -m pip install -r requirements.txt
   python manage.py migrate
   python manage.py runserver 8000
   ```

2. В іншому терміналі, з кореня цього репозиторію, віддати файли статичним
   сервером на порту 3000:

   ```bash
   python -m http.server 3000
   ```

3. Відкрити http://localhost:3000 у браузері.

- Frontend: http://localhost:3000
- Backend: http://127.0.0.1:8000 (API: http://127.0.0.1:8000/api/v1)

Порт 3000 обов'язковий: CORS на бекенді дозволяє запити лише з `http://localhost:3000` і `http://127.0.0.1:3000`. Якщо бекенд не запущено, сторінка покаже помилку "API at http://127.0.0.1:8000 is not running."

## Структура

- `index.html` - каркас сторінки: верхня панель, рядок статусу, `<main id="app">`
- `css/style.css` - стилі (палітра як CSS custom properties)
- `js/api.js` - запити до API (`api()`, `ApiError`) і хелпери для DOM (`el()`, `link()`)
- `js/views.js` - по одній функції на сторінку (`renderHome`, `renderBoard`, `renderThread`, `renderTags`, `renderNotFound`)
- `js/forms.js` - побудова форм, кнопки дій і видалення, показ помилок
- `js/app.js` - роутер: читає `location.hash` і показує потрібну сторінку
